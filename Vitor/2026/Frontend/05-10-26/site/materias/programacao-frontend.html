Questão 14

"O Gulp é um automatizador de tarefas baseado em fluxos (streams) no Node.js. Ele permite definir tarefas em JavaScript e encadeá-las para automatizar processos do desenvolvimento, utilizando recursos como src(), dest(), series() e parallel(). Os arquivos podem passar por diferentes etapas de transformação por meio de pipelines de streams."

Fonte: https://gulpjs.com/docs/en/getting-started/working-with-files/.

Um projeto web necessita de uma rotina automatizada no ambiente local que, a cada alteração nos arquivos fonte, realize sequencialmente a compilação do código Sass para CSS, a minificação do arquivo final e o recarregamento automático do navegador. Considerando as necessidades operacionais descritas no suporte, analise as alternativas e assinale aquela que apresenta a solução tecnicamente adequada para a automação desse fluxo.

  1. Utilizar o Nginx para efetuar a compilação de arquivos e a minificação de estilos CSS a cada alteração no código.
  2. Utilizar o Gulp para definir tarefas automatizadas que processem o código Sass, minifiquem o CSS e otimizem os artefatos.
  3. Utilizar o MySQL para gerenciar a execução em tempo real das rotinas de atualização de pré-processadores do front-end.
  4. Utilizar o RabbitMQ para realizar a otimização direta de imagens e a substituição do servidor de arquivos estáticos.
  5. Utilizar o Docker para realizar a alteração de sintaxe dos arquivos Sass diretamente no navegador do usuário final.
Ver resolução

Alternativa correta: B. O Gulp é um task runner voltado a automatizar rotinas de compilação de pré-processadores (como Sass), concatenação, compressão de arquivos e live reload no desenvolvimento web.

Porquê: Nginx serve arquivos, MySQL guarda dados, RabbitMQ enfileira mensagens, Docker isola ambientes — nenhum é task runner de build front-end.

Questão 16

O CSS Grid Layout oferece um sistema de layout bidimensional baseado em colunas e linhas. A combinação de propriedades grid com media queries permite reestruturar a disposição espacial dos elementos de acordo com as características da tela.

Fonte: https://developer.mozilla.org/pt-BR/docs/Learn/CSS/CSS_layout/Grids (adaptado).

A equipe de front-end desenvolveu a estrutura abaixo para organizar os dados de um painel de indicadores em telas desktop e dispositivos móveis:

.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
@media (max-width: 768px) {
  .container {
    grid-template-columns: 1fr;
  }
}

Analise as regras CSS apresentadas no suporte técnico e assinale a alternativa que prevê corretamente o comportamento do layout.

  1. O layout renderiza três colunas de largura equivalente em telas maiores que 768px e passa a renderizar uma única coluna quando a largura da janela é igual ou inferior a 768px.
  2. O layout mantém obrigatoriamente três colunas em todas as resoluções de tela, aplicando a regra @media apenas para remover o espaçamento de 16px.
  3. O layout expande o número de colunas para quatro em dispositivos com telas menores que 768px devido à redistribuição da unidade proporcional 1fr.
  4. A propriedade grid-template-columns: 1fr dentro da media query é ignorada pelo navegador por conflito direto com o tipo de exibição display: grid.
  5. A estrutura utiliza o sistema unidimensional Flexbox e altera as colunas exclusivamente quando a resolução da tela ultrapassa 768px.
Ver resolução

Alternativa correta: A. A regra base define três colunas iguais de fração flexível (repeat(3, 1fr)). A consulta de mídia @media (max-width: 768px) sobrescreve essa divisão em visores de 768px para baixo, empilhando todo o conteúdo em uma coluna (1fr).

Porquê: max-width atua de 768px para baixo (não para cima); 1fr sozinho = 1 coluna; e o código usa Grid, não Flexbox.

Questão 17

A API WebSocket é uma tecnologia que permite abrir uma sessão de comunicação interativa bidirecional entre o navegador do usuário e um servidor. Com essa API, é possível enviar mensagens para um servidor e receber respostas orientadas a eventos sem a necessidade de realizar consultas periódicas para obter atualizações.

Fonte: https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/index.html (adaptado).

Um dashboard precisa receber notificações instantâneas do servidor sempre que o estado de um processamento interno for alterado, sem a necessidade de realizar requisições HTTP repetitivas a cada poucos segundos. Preencha as lacunas: "A API [lacuna 1] permite estabelecer uma comunicação [lacuna 2] entre o navegador e o servidor sobre uma única conexão. Isso possibilita o envio e recebimento de dados orientados a [lacuna 3], eliminando a necessidade de consultas periódicas ao servidor, técnica conhecida como [lacuna 4]."

  • Lacuna 1: WebSocket
  • Lacuna 2: bidirecional
  • Lacuna 3: eventos
  • Lacuna 4: polling
Ver resolução

Preenchimento correto: WebSocket · bidirecional · eventos · polling.

Porquê: a consulta contínua por meio de requisições HTTP repetidas é chamada de polling (ou long polling). O WebSocket resolve esse gargalo abrindo um canal persistente, bidirecional e orientado a eventos sobre uma única conexão TCP.
